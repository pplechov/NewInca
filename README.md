# newINCA

Чтение проектов INCA (`.ipj`, `.ipl`) **от разных приборов и разных версий
INCA**, экспорт изображений и количественный пересчёт спектров в оксиды — без
установленной INCA.

Собрано и проверено на Windows 11 x64 и macOS 26.6.2 (Apple Silicon) с Python 3.12 и PyInstaller 6.22.

## Готовые сборки

**macOS (Apple Silicon).** [Скачать newINCA.app в ZIP](https://github.com/alyon-a/NewInca/raw/refs/heads/main/macos/newINCA-macOS-arm64.zip).
Распакуйте архив и откройте `newINCA.app`. Python и шесть профилей калибровки входят в приложение.
Результаты по умолчанию сохраняются в `~/newINCA/out`.

Скачать: **[Releases → newINCA 1.0.0 (Windows x64)](https://github.com/pplechov/NewInca/releases/latest)** —
архив `newINCA-1.0.0-win64.zip` (≈35 МБ): `newINCA.exe`, `newINCA-cli.exe`, `_internal\`,
`calibration\`, `points\`, `tools\`. Распаковать целиком в любую папку и запустить
`newINCA.exe`; Python и INCA не нужны.

## Быстрый старт

1. Запустить `newINCA.exe`.
2. **Открыть проект…** → выбрать `.ipj` (или `.ipl`).
3. В журнале появятся строки о том, **что это за файл**: контейнер, семейство
   прибора, детектор, сколько образцов/участков/спектров/изображений и есть ли
   координаты точек. Программа сама подберёт калибровку по серийному номеру
   детектора (её можно сменить списком «Калибровка» справа сверху).
4. Слева появится дерево: образец → участки, с числом изображений и спектров.
5. **Экспорт изображений и расчёт** → в `out\` появятся:
   - `images\<участок>_<id>.png` — изображение **как есть**;
   - `images\<участок>_<id>_annotated.png` — оно же **с точками и названиями анализов**
     (координаты берутся из самого проекта, см. ниже);
   - `images\<участок>_<id>_analyses.png` — таблица анализов, если у участка
     **нет растра** (так бывает в проектах, где сохранены только спектры);
   - `quant.csv` — оксиды, мас.%, по каждому анализу;
   - `points.csv` — координаты всех точек и линий в пикселях изображения.

Кнопка **?** рядом со списком калибровок показывает активный профиль, папку и
все доступные профили.

### Просмотр спектров

Список анализов участка — в правой нижней части окна. Щелчок по номеру:

* рисует **сам спектр** (0–20 кэВ) с выбором логарифмической или линейной
  шкалы интенсивности и подписями линий из `PeakLabels`. Ползунок «Порог
  подписей» задаёт минимальную высоту пика в процентах от максимума спектра.
  По умолчанию порог равен 6 %. При 0 % показываются все сохранённые метки
  в диапазоне графика, в том числе несколько линий одного элемента;
* подсвечивает жёлтым соответствующую площадку на изображении;
* показывает **под спектром информацию по анализу**: участок, номер, id
  спектра, ускоряющее напряжение, живое и реальное время, дату съёмки, полное
  число импульсов, перечень элементов и оксиды в мас.% с суммой.

Расставлять точки вручную больше не нужно — координаты берутся из проекта, а
режим расстановки убран.

### Запоминание папок

Стрелка рядом с кнопкой «Открыть проект…» показывает до десяти недавно
открытых проектов. Список сохраняется между запусками.

Программа помнит последнюю папку проекта, папку вывода, размер и положение
окна (в `%APPDATA%\newINCA\ui.ini`), поэтому следующее «Открыть проект…»
начинается с той же папки.

## Разные версии проектов и разные приборы

Формат `.ipj` — контейнер OLE2/CFBF, внутри дерево папок (storages) и потоков
(streams). Имена **листьев** одинаковы во всех встреченных версиях INCA
(`IIncaProjectInfo`, `IFOVInfo`, `XrayData/Spectrum`, `ChordList/ChordList`,
`GreyImage/micromap`, …), а вот всё остальное различается: глубина дерева,
наличие промежуточных папок, состав приборной части, разрядность изображений,
записан ли `ChordList`.

Поэтому чтение идёт **по роли, а не по фиксированному пути**: каждый объект
ищется по списку известных имён (без учёта регистра, на любой глубине), а не по
«третьему уровню вложенности». Что программа определяет и учитывает:

| Что | Варианты, которые встречаются |
|---|---|
| Семейство прибора | `ISIS`/Camebax (`XrayDetector/ISIS_Processor`), `XStream` (`XStreamProcessor`, XGT2, X-Max) |
| Детектор | модель (`X-Max 7`) и серийный номер из `ED_Detector` — по ним выбирается калибровка |
| Образцы и участки | несколько образцов; `FOVs` может отсутствовать (участок = сам образец) |
| Изображения | 8-битные (тег `0x0011`) и **16-битные** (тег `0x0002`); папки `Images` может не быть вовсе |
| Координаты анализов | `ChordList` с точками, пустой `ChordList` (10 байт, счётчик 0), отсутствующий `ChordList` |
| Спектры | обычный анализ и `CalibSpectrum`; 1K/2K/4K каналов — по длине потока |
| Установочные проекты | файлы `Installation.ipj` (`DetectorTest`, `SystemSetUpData`, …) распознаются и помечаются |

Проверено на 13 проектах: Camebax (INCA 6.1.14, ISIS), XStream/X-Max 7 (МГУ),
XStream/Brown, установочные файлы детекторов. `newINCA.exe selftest <папка>`
проходит по всем и печатает, что в каждом прочитано и что выглядит подозрительно.

Подробнее о том, что именно нашлось в файлах:

* **Глубина дерева.** В одних версиях спектры лежат в
  `Samples/SMP…/FOVs/FOV…/Spectra/SPE…/`, в других `Images` и `Spectra`
  отсутствуют, а данные — прямо в участке. Жёсткие пути `len(path)==7` ломались
  на первом же незнакомом варианте; теперь поиск идёт по именам.
* **Образцы.** Раньше участки собирались по всему файлу и **дублировались** у
  каждого образца (в проекте МГУ два образца показывали одни и те же участки).
  Теперь участок принадлежит своему образцу.
* **Изображения 8 и 16 бит.** Заголовок `micromap` — 26 байт, затем растр,
  затем постоянный хвост 222 байта. Разрядность задаёт слово по смещению
  `0x18`: `0x0011` — один байт на пиксель, `0x0002` — два. В проектах
  `recovery.ipj` (Camebax и Brown) и в установочных файлах МГУ картинки
  **16-битные**; прежняя версия читала их как 8-битные и показывала мусор.
  Для показа 16-битный растр масштабируется по уровню отображения из заголовка
  (он равен максимуму кадра), а если уровень не задан — по перцентилям.
* **Пустой `ChordList`.** Проект, в котором сохранены только спектры, пишет
  10-байтовый `ChordList` со счётчиком 0. Это не ошибка: программа так и
  сообщает — «координаты не сохранены», и выносит состав анализов в таблицу.

## Командная строка

```bat
newINCA-cli.exe list     "D:\...\проект.ipj"
newINCA-cli.exe info     "D:\...\проект.ipj" [--json]
newINCA-cli.exe export   "D:\...\проект.ipj" "D:\результаты" [--profile ИМЯ]
newINCA-cli.exe quant    "D:\...\проект.ipj" "D:\результаты" [--profile ИМЯ]
newINCA-cli.exe profiles
newINCA-cli.exe selftest "D:\проекты"
```

`info` — что за файл и какая калибровка к нему подобрана (с `--json` — машинно
читаемо). `profiles` — список калибровок и какая активна (`*`). `selftest`
читает все `.ipj`/`.ipl` в папке и печатает таблицу: семейство, образцы,
участки, спектры, изображения, точки, калибровка, плюс предупреждения
(например, «точка за пределами кадра»). `export` делает и изображения, и
расчёт. `quant` — только таблицу. Вывод в UTF-8, кириллица в консоли
отображается корректно.

## Изображения

В проекте `micromap` — растр с 26-байтовым заголовком:

```
0x00 dword  версия (8)
0x08 double уровень отображения (равен максимуму кадра)
0x10 dword  ширина
0x14 dword  высота
0x18 word   формат пикселя: 0x0011 = 8 бит, 0x0002 = 16 бит
0x1A        ширина*высота*(1 или 2) байт серого, little endian
...         постоянный хвост 222 байта
```

`26 + W*H*(1|2) + 222` точно равно длине потока. Если читать с 248 байт (а не с
26), растр сдвигается на 222 байта и левая полоса уезжает вправо — эта ошибка
была в первой версии и здесь исправлена. Разрядность берётся из заголовка, а не
угадывается по длине, но если длина с заголовком не сходится, растр не
сдвигается: он обрезается или дополняется, и в журнале появляется
предупреждение.

## Точки анализов

Координаты **есть в самом проекте**. Они лежат в потоке

```
Samples/<образец>/FOVs/<участок>/Spectra/<спектр>/ChordList/ChordList
```

и именно по ним INCA рисует пронумерованные точки поверх изображения.
Формат (проверен на пяти проектах: `Плечов_2018_Jan4`, `Плечов_FN_1071`,
`Плечев_1610`, `2018-01-13`, `Капланская`):

```
0x00  float   масштаб, во всех проектах 1.0
0x04  uint16  ширина изображения в пикселях (512, 1024) — для проверки
0x06  uint32  число точек
0x0A          число_точек × (uint16 строка, uint16 столбец, uint16 тип)
```

Важно: INCA пишет пару как **(строка, столбец)**, то есть сначала `y`, потом
`x`. Это не догадка: второе значение ограничено шириной изображения и может
превышать его высоту (например, 861 при кадре 1024×832), а если рисовать
`x = столбец, y = строка`, то яркость BSE совпадает с составом анализов
(r = 0.80 между серым и Fe+Ti+Mg по 19 точкам проекта `Плечов_2018_Jan4`;
при обратном чтении r = 0.13). Поэтому в коде точка — это `(x, y) = (col, row)`.

Обычный анализ — одна точка, линейное сканирование — вертикальная ломаная из
десятков точек (`тип` = код слоя/цвета, для геометрии не нужен).

Форма метки зависит от способа накопления.

* линейное сканирование — прямоугольник по габаритам ломаной (сторона не меньше
  11 px, чтобы тонкий растр оставался виден), внутри бледно показана сама линия
  растра;
* точечный анализ — небольшой кружок с центром в координатах съёмки.

Номер подписан рядом на тёмной плашке, чтобы читался и на светлом, и на тёмном
фоне изображения.

В `out\points.csv` выгружается таблица:

```
sample;site;fov_id;spectrum;label;point;n_points;type;x;y
```

Файл-спутник `points\<проект>.csv` (`fov;x;y;label`) остался только для
проектов, где координат в `ChordList` нет (например, старые съёмки с пустым
списком). Если координаты в проекте есть, файл-спутник не используется:
приоритет у INCA. Сам `.ipj` не изменяется.

Если координат нет совсем, программа не выдумывает их: на изображение
выносится легенда со всеми анализами участка и их составом, и об этом
написано в подписи под картинкой. Если у участка нет и изображения, легенда
сохраняется отдельной картинкой `<участок>_<id>_analyses.png`.

## Калибровка — отдельно, по приборам

Количественный расчёт не встроен в программу, а читается из `calibration\`:

* `xpp_standards.csv` — та самая таблица, что лежит в INCA
  (`XPP Standards.mdb`), экспортированная без изменений: состав стандарта,
  измеренная интенсивность (`Norm Area Std`), линия, энергия, геометрия;
* `mac.csv` и остальные — физика.

У каждого прибора и даже у каждого протокола измерения стандартов — своя
таблица, поэтому они лежат профилями в `calibration\profiles\<имя>\`:

```
profiles\msu-cpx-opx-amp-bt\xpp_standards.csv   таблица стандартов
profiles\msu-cpx-opx-amp-bt\profile.ini         прибор, детектор, описание
```

`profile.ini` содержит серийный номер детектора (`detector_serial`), модель,
напряжение и признак `default`. При открытии проекта программа читает
`ED_Detector` из файла и подбирает профиль:

1. сохранённый ранее выбор для этого серийного номера (`settings.ini`);
2. профиль с таким же `detector_serial`;
3. профиль с такой же моделью детектора;
4. профиль по умолчанию (`calibration\xpp_standards.csv`).

Подобранный профиль виден в журнале, в статусной строке и в `info`, сменить
можно списком «Калибровка»; выбор запоминается для этого детектора. Чтобы
добавить новый прибор, достаточно создать папку с `xpp_standards.csv` и
`profile.ini` — пересборка не нужна. Переменная окружения `NEWINCA_CALIB`
заменяет корень калибровки целиком.

Базы стандартов INCA — это Access 97 (Jet 3), который не читается современными
драйверами; готовые CSV для МГУ уже лежат в `profiles\`, а для новой базы есть
`tools\mdb_export.cmd` (см. `calibration\SOURCE.md`).

Если калибровочных файлов нет, программа всё равно откроет проект и сохранит
изображения, только без таблицы концентраций.

## Что считается

Порядок: интегрирование пиков над локальным фоном → k-отношение по таблице
стандартов → ZAF-поправка с итерацией до нормировки на 100 %.

Элементы берутся из **самого проекта**: в потоке `Elements` INCA хранит список
элементов, которые искала съёмка (по одному dword на атомный номер, со сдвигом
2). Программа считает только их (плюс кислород — он нужен для матрицы
поглощения). Это принципиально для чужих приборов: в хромитовой пробе
`Cr Kβ` (5.95 кэВ) попадает в окно `Mn Kα` (5.90 кэВ), и без списка элементов
программа выдавала «MnO 12 %» там, где марганца нет.

Если списка элементов в проекте нет, считаются все элементы таблицы
(`O, Na, Mg, Al, Si, K, Ca, Ti, Mn, Fe`).

## Точность

Проверка на K-полевом шпате (KAlSi₃O₈) из проекта `Плечов_2018_Jan4.ipj`,
7 анализов:

| оксид | идеал | расчёт (среднее ± σ) |
|---|---|---|
| SiO₂ | 64.65 | 64.43 ± 0.45 |
| Al₂O₃ | 18.43 | 17.19 ± 0.58 |
| K₂O | 16.92 | 17.25 ± 0.33 |

Кварц даёт SiO₂ = 100.0: результат нормируется на 100 %, поэтому единственный
оксид всегда даёт 100. Реальная точность — порядка ±1.5 мас.% по основным
оксидам, воспроизводимость ~0.5 мас.%.

Это не XPP от INCA: модель φ(ρz) и таблицы поглощения Oxford закрыты, поэтому
последние ~1.5 мас.% будут отличаться от того, что печатает INCA. Числа
независимые, а не перепечатка исходного отчёта.

## Ограничения

* Наложения линий не разложены: используются Kα O, Na, Mg, Al, Si, K, Ca, Ti,
  Mn, Fe. Хром, никель, сера и другие элементы читаются из проекта и попадают
  в список элементов, но в оксиды не пересчитываются (их Kβ-линии могут
  попадать в окна Mn/Ti — поэтому важен список элементов проекта).
* Поглощение считается с матричным согласованием стандарта только для тех
  стандартов, чей состав известен (`STD_COMP` в `analysis.py`); для остальных
  поправка не вводится.
* Спектры, где выше нуль-пика ничего нет (неудавшаяся съёмка), помечаются как
  «неудачная съёмка» и в расчёт не идут.
* Если в проекте есть список элементов, но ни один из них не даёт оксида
  (например, Cu-Zn-S), строка помечается «нет оксидов» и в таблице стоит «—».
* `.ipl` читается тем же разборщиком, что и `.ipj` (это тоже OLE2-контейнер);
  если встретится другая структура, программа сообщит об ошибке.

## Совместимость с INCA

* Файлы INCA **только читаются** и никогда не изменяются: `.ipj` остаётся
  байт в байт таким, каким его записала INCA. Координаты точек берутся из
  `ChordList`, результаты пишутся в отдельные файлы, поэтому проект можно
  открыть в INCA как обычно.
* Используется **родная** таблица стандартов INCA, а не пересчитанная заново,
  так что чувствительности — те, на которых прибор калибровали.
* Обратная запись в формат `.ipj` сознательно не делается: это закрытый
  формат, и молча испортить проект хуже, чем не уметь его сохранять.

## Сборка из исходников

На macOS с установленными Python 3.12 и Apple Command Line Tools выполните эти команды в корне репозитория.

```sh
python3 -m pip install pyinstaller pillow numpy
./build-macos.sh
```

Готовое приложение появится в `dist/newINCA.app`.

На Windows выполните команды в командной строке.

```bat
python -m pip install pyinstaller pillow numpy
cd src
python -m PyInstaller --onedir --noconsole --name newINCA_gui main.py
python -m PyInstaller --onedir --console  --name newINCA_cli main.py
```

Затем переименовать `newINCA_gui.exe` → `newINCA.exe`, `newINCA_cli.exe` →
`newINCA-cli.exe` и положить рядом общий `_internal` и папки `calibration`,
`points`, `tools`. Оба .exe собираются из одного `main.py`, поэтому набор
библиотек в `_internal` у них одинаковый.
